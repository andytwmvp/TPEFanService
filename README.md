# TPEFanService

烏梅劇院偶像視角、觀眾與座位模擬、找粉絲遊戲，以及彩帶挑戰。直接開啟 [GitHub Pages](https://andytwmvp.github.io/TPEFanService/)。不需要建置；Pages 使用 `feature/ribbon-throw-game` 分支根目錄。

## 彩帶挑戰

選擇隊伍與起始成員，按「開始遊戲」，再選「彩帶投擲挑戰」。準備完成後，從 3D 畫面向上快速滑動；速度控制力度、左右傾斜控制方向。綠色是直滑命中區間、黃色是完美接取區間；方向容許值以中央力度為準，拖動時會另外用當下力度和角度預測結果。請在畫面下方開始滑動，避開按鈕與資訊面板。

舞台使用 14 個虛擬站位：正面六個，左、右側各四個。正面依實際可用舞台寬度分散，避開柱體正前方；選擇隊伍與起始成員後，先由該成員出手，其餘站位隨機輪替。Team P 使用既有 14 位成員；Team TIII 使用既有 13 位成員，不足的一格顯示「虛擬站位」，不重複或新增成員資料。

正面站位只選正面 A–D 排觀眾；左側站位只選 N／O 排，右側只選 P／Q 排。優先找出手成員的粉絲，不可達時再試同區其他現有觀眾。鏡頭、模型右手、預覽、命中區間與真實投擲使用同一站位；搜尋中不能投擲。柱子會實際碰撞、反彈，遮住的目標不納入搜尋，接取及撿取也不能隔柱成功。金色圈心直接對準物理接取點，出畫面或被柱體遮住時隱藏；開始滑動與放手出手都會檢查，圈心不可見時不建立投擲、不計次，會先取消手勢並重新對準或選目標。也會確認出手點仍在鏡頭內，不會夾到邊緣假裝仍對準。

依使用者指定的三輪規則，每輪完整投十次後判定：

| 輪次 | 過關門檻 |
| --- | --- |
| 第一輪 | 十投至少四中 |
| 挑戰輪 | 十投至少六中 |
| 決勝輪 | 十投十中，達成即通關 |

被其他觀眾接走算失手；落地撿取可以命中，但不算完美，碰撞也不算完美。可提前結束、重玩或返回選單。背景切換會取消尚未完成的滑動，暫停物理、搜尋及回合時間，回來後重新滑動即可。

結果保留彩帶，14 個舞台模型會集合拍照。鏡頭平順移到 A 排正中央的坐席視線；桌面採適度廣角，手機聚焦中央成員，允許裁掉兩側，不以超廣角縮小人物。約 2.8 秒後顯示沿用原找粉絲遊戲樣式的結果卡，包含三輪各自的命中、門檻與過關狀態。合照固定為 1200 × 920，使用獨立橫向鏡頭保留完整成員；按「儲存合照」，手機也可長按圖片儲存。

實績與 12 個稱號儲存在本機瀏覽器，新增 N／O／P／Q 側席送達／完美記錄；原正面 A–D 排收藏條件保留。虛擬站位的投擲仍計入當次分數與過關判定，但不冒用真實成員的收藏格。禁用儲存時會顯示提示。離開彩帶模式會移除本模式新增的模型與資源，還原原遊戲的八個模型。

## 開發與驗證

```sh
npm ci
# Linux 安裝 Chromium，或設定 CHROMIUM_PATH 指向可用的 Chromium。
npm test
# Pages 部署後，直接驗證公開站（不攔截正式資源）：
node tests/pages-smoke.cjs
RIBBON_VERIFY_ZONES=1 node tests/ribbon-live.cjs
```

測試透過攔截 HTML 在記憶體中加入測試介面，正式檔案不暴露測試 API。流程測試停止自動 RAF，直接驅動固定步進與 visibility 事件；UI 測試使用 WebGL、Chromium 原生滑鼠／觸控輸入、桌面及手機 viewport，輸出 `tests/artifacts/`。這些測試不代表實體手機或硬體 GPU 驗收。

`ribbon-world.js` 從 TPE 畫面實際的舞台、平台、座椅、柱牆與燈具 box 網格建立空間索引與旋轉包圍盒窄相碰撞。預覽、搜尋和真實投擲共用 `ribbonStepRoll`。彩帶節點以 1/120 秒固定步進運作；接取後穩定或九秒後休眠，保留幾何，只在端點移動時喚醒，鏡頭位置改變時更新展示網格。

詳細驗證與差異見 [VALIDATION.md](VALIDATION.md)，原站來源與授權狀態見 [SOURCES.md](SOURCES.md)。
